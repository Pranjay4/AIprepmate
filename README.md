# GDiscuss — MBA Placement GD Simulator

An AI-powered Group Discussion simulator: you sit in on a realistic MBA placement
GD alongside 5–9 distinct AI candidates (an analyst, an aggressive speaker, a
knowledgeable-but-occasionally-wrong candidate, a balanced synthesizer, a creative
reframer, a weaker generic speaker, and more), with a non-scripted turn-taking
engine, live or end-of-GD coaching, and a detailed placement-style evaluation
report afterward.

## Setup

1. Install dependencies:
   ```bash
   npm install
   ```
2. Copy the env template and add **one** AI provider key:
   ```bash
   cp .env.local.example .env.local
   ```
   Set `AI_PROVIDER` to `anthropic`, `openai`, or `gemini`, and fill in the
   matching API key (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, or `GEMINI_API_KEY`).
   Only the key for the selected provider is required.
3. Run the dev server:
   ```bash
   npm run dev
   ```
   Open [http://localhost:3000](http://localhost:3000).

Without a valid key, the app will fail with a clear "X_API_KEY is not set" error
when you try to start a GD, rather than crashing.

## Architecture

- **Frontend**: Next.js (App Router) + TypeScript + Tailwind, Zustand for live
  session state.
- **Backend**: Next.js route handlers under `app/api/*` — no separate server.
- **AI provider abstraction**: `lib/ai/providers/*` — Anthropic, OpenAI, and
  Gemini adapters behind one `AIProvider` interface, selected via `AI_PROVIDER`.
  Structured JSON output is validated with Zod on every call.
- **Separate system prompts** per engine, not one giant prompt:
  `lib/ai/prompts/{topicGenerator,participant,evaluator,coach,rebuttal}.ts`.
- **Turn-taking engine** (`lib/turnEngineLogic.ts`): deliberately pure TypeScript,
  not an LLM call — computes who speaks next from recency, persona traits,
  rebuttal-worthiness, randomness (scaled by the "chaos" setting), and how long
  the human has been silent. Only the *content* of an AI turn is generated by
  the LLM (`lib/ai/participant-engine.ts`).
- **Evaluation** (`lib/ai/evaluator.ts`): scores only the user, out of 100 across
  the 8 weighted dimensions, and produces the "improved version" / "best possible
  answer" pair plus counterargument training in one structured call.
- **Persistence**: no backend database — completed sessions, your profile, and
  realism settings are stored in the browser via `localStorage`
  (`lib/storage/*`). Nothing leaves your machine except the LLM API calls
  themselves.
- **Voice mode**: the browser's native Web Speech API — no extra service. Pace,
  filler-word, and pause metrics are explicitly labeled as estimates
  (`lib/fillerWordAnalysis.ts`), not a validated confidence measurement.

## Notes on scope

- The end-of-GD report generates "improved version" / "best possible answer"
  rewrites for your **top 3** most substantive interventions, not literally
  every line, to keep latency and cost reasonable.
- Session history and coaching trends live only in your browser's
  `localStorage` — clearing site data resets them.
